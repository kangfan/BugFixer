# 0.3.1普通修复交付流水线

单一MCP入口deliver_repair（CLI：bugfixer deliver）。inspect读取来源/授权、Git、禅道表单和原群成员，集中返回缺项；run绑定预检hash，在程序内部连续执行；status读取本地进度。Agent只负责具体修复、语义判断和必要的人工作决策，不在每个机械步骤间调用模型。

适用输入、授权记录和运行说明见[交付skill](../.agents/skills/bugfixer-context/references/delivery.md)。新MCP进程加载第四个工具，已启动进程需重连，CLI立即可用。fetch和独立prepare/apply保持兼容。

本机SQLite新增delivery_jobs与delivery_approval_uses。审批仍读取agent-workspace.sqlite3/profile=local：工具只创建pending，不创建approved。新式批准必须有真实owner的approvedBy、明确confirmed_actions及范围，元数据选择不等于批准动作。审批消费绑定编号/Bug/job，不能换job复用已用确认；来源analysis_only和执行开关优先。

已认证的国内普通维修请求沿用现有授权，不增加主人逐条批准：宿主在既有任务中记录ordinaryDeliveryAuthorization，绑定来源、真实发起人、Bug/工程/分支/文件范围和解决版本，工具复核后使用。普通成员的测试豁免标记不生效；海外及不支持的特殊范围仍保持旧门禁。这个结构是宿主对既有请求的记录，不是工具参数自授权限。

普通批次采用一个精确范围提交，消息列出所有Bug；检查工作区原始SHA256及Git clean/CRLF后的blob对象，保留未选择修改，不擅自处理已有暂存。提交/推送intent先持久化；崩溃后的进程锁自动释放，恢复只能依据确定证据继续，不能证明时返回uncertain。每个写入边界再次核验批准；源表、AOT/Main/JS、子模块、发布等不在自动范围。

禅道逐项复用0.2预览/执行和只读对账，不新造重复写接口。默认解决转给实时Bug创建人。DWS固定原组织机器人：群来源一条消息同时@认证调用者与创建人；原主人私聊来源才另外反馈该原私聊。没有转交记录的桌面调用者通过工具结果返回当前聊天，不推断钉钉身份。每个角色单独记录notification_coverage；创建人定向通知获批豁免时标为waived。

0.3.1针对两次实际维修发现补齐三处自动处理：中文单行提交说明含全部Bug号和job标记，钩子仅压平换行/空白时继续严格校验父提交、文件集与blob；通知直接调用官方DWS二进制，以UTF-8 bytes/LF输入，dry-run核对正文后发送；在程序内读取原群完整正文并核对对象覆盖。实质提交差异仍停止，不禁用hooks。

成功发送与全文读回分别持久化。读回延迟或发送响应丢失时，同job run只读查证，不重发；明确预发送失败与未知服务结果区分记录。通知前实时核对创建人、resolved/fixed及最终指派；正常情况下Agent无需再手动amend、拼DWS命令、复查已核验回执或补发同一通知。

程序的确定性调用不使用大模型。一次正常修复后交付为inspect和run两次工具调用；缺批准时返回一次完整问题清单，实际批准仍由有权用户作出。日志/差异/回执不全量回传模型，只返回状态、提交号、必要错误和证据路径；此处没有承诺实际token节省百分比。

新增流水线验收使用固定临时目录的真实Git工作仓库和本地裸远端，禅道及DWS为模拟；没有重新处理此前6条业务Bug，没有真实远端推送或发消息。底层0.2回填的真实验收与新增编排的模拟验收分别记录。
